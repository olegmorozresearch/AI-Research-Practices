# Contributing to AI Research Practices

## 1. Модель співпраці

Це **вихідний (`upstream`) репозиторій навчальних матеріалів**, а не колективне сховище результатів студентських досліджень. Студент працює у **власному fork**. Його дослідницькі артефакти й рукописи не потрібно надсилати в upstream.

## 2. Старт роботи студента

1. Створюємо **Fork** репозиторію у власному GitHub-акаунті.
2. Відкриваємо відповідний спринт у `01-research-practice/`.
3. Працюємо зі своїми матеріалами у fork, робимо зрозумілі коміти та зберігаємо історію дослідження.
4. Для отримання оновлень виконуємо **Sync fork** вручну; GitHub не переносить нові зміни з upstream автоматично.
5. Перед синхронізацією перевіряємо власні незбережені зміни. Якщо студент змінював той самий навчальний файл, можливий конфлікт.

**Практична порада:** зберігаємо свої результати в окремих файлах і робочих каталогах fork, не переписуючи без потреби оригінальні навчальні матеріали. Робочі каталоги на кшталт `research_artifacts/` не входять до початкового upstream, але можуть містити власні версіоновані результати у fork.

## 3. Межі використання upstream

Вихідний репозиторій призначений для розповсюдження навчальних матеріалів і підтримується його власником. **Студенти не подають до upstream Issues, Pull Requests, власні результати, рукописи чи інші файли.**

Усі навчальні та дослідницькі зміни студенти виконують у власних forks. Оновлення навчальних матеріалів із upstream отримуємо за допомогою **Sync fork**. Зауваження, пропозиції та повідомлення про помилки в навчальних матеріалах надсилаємо електронною поштою на **адресу для зворотного зв’язку**, зазначену в [`general-provisions.md`](general-provisions.md), а не через GitHub Issues або Pull Requests. Запитання щодо індивідуального дослідження й виконання практики адресуємо своєму науковому керівнику через погоджені канали комунікації.

## 4. Правила підтримки навчальних матеріалів власником репозиторію

- Зберігається узгоджена структура спринтів та термінологія.
- **`.ipynb` — основний навчальний формат; `.md` має відповідати його змісту.** 
- Дослідницький протокол і фактичні результати навчального прикладу не змінюються без обґрунтування й попередньої перевірки.
- Шаблони й приклади розміщуються в каталозі відповідного спринту і не дублються між розділами.
- Для коду вказується мінімальний спосіб відтворення.

## 5. Керування доступом до upstream

Публічний репозиторій доступний лише для читання та створення forks. **Права запису до upstream мають лише власник і явно уповноважені ним особи**. Для репозиторію вимкнено GitHub **Issues** та **Pull Requests**.

Наукові рукописи й артефакти передаємо на рецензування керівнику за процедурою [Review and Publication Policy](REVIEW_AND_PUBLICATION_POLICY.md), а не через upstream.

## 6. Авторство та права

Внесок до навчального репозиторію й наукове авторство статті — різні речі. Співавторство наукових публікацій визначається реальним інтелектуальним внеском, а не фактом використання GitHub або проведення review.

Перед додаванням сторонніх текстів, зображень, даних або коду перевіряємо право їх поширювати та відповідні ліцензії.
